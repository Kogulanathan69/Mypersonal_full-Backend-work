# M4-owned persistence

BE-M4-D02a foundation (G03: conditional internal development and compatibility testing authorization; commercial licence review pending):

- `BuildMindDbContext`: no feature entities yet. Feature mappings go in `Configurations/<Feature>/` as `IEntityTypeConfiguration<T>` classes, **only with the owning member's agreement**.
- `MySqlContextOptions`: the single provider configuration (no retries, no sensitive logging).
- `DesignTime/`: the `dotnet-ef` factory, which reads only `BUILDMIND_MIGRATIONS_CONNECTION`.
- `Transactions/TransactionRunner`: one atomic operation per transaction; a failed commit means the outcome is unknown and is never retried.
- `Errors/PersistenceErrorClassifier`: safe classification of MySQL and EF failures.
- `MySqlModelConventions`: every timestamp is stored as a **UTC** `datetime(6)`. `DateTimeOffset` values are converted to their UTC instant and read back at +00:00 (the original offset is not kept); `DateTime` must be UTC, and Local/Unspecified values are rejected. This is needed because the provider's own `DateTimeOffset` **materialisation (read) path** drops microseconds, even with `datetime(6)`: storage and parameters keep them (CI T19D, run 44301027243).
- `Migrations/`: none yet. Migrations are generated by M4, reviewed as **ranged** scripts (from the last applied migration to the target) and applied manually with the migration account. Idempotent scripts can't be executed with this provider (see `tools/database/mysql/README.md`). The application never migrates itself.

The database is disabled by default (`Database:Enabled=false`). For internal development, MySQL 8.4 compatibility is verified by the spike (`tests/BuildMind.Persistence.IntegrationTests`): 28/28 passed in CI run 44301027243, with two documented provider limitations. Provider acceptance for production and commercial use (G03) is still open.
