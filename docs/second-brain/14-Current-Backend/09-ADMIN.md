# Admin, delegated staff and governance

Two primary categories: Customer and Admin. Staff are delegated admin-created accounts, not a third primary category; enforce separate delegated permission policy. Main Admin creates staff accounts, assigns module scope, can review the same module contents. Staff may view assigned module; all add/edit/delete proposals remain pending until main admin approves, across every assigned module. Reject leaves live state unchanged. Main admin performs review against base version, records actor/timestamp, applies atomically, handles stale proposal conflict. Store hashed credentials; initial credentials delivered securely, not plaintext in DB/logs. Require password change for temporary password if approved. No privilege escalation or access to unrelated modules.

Candidate admin backend slices: staff provisioning, module assignments, pending change queue, regulatory document/rule publication and review, scoped customer/subscription management only if approved.
