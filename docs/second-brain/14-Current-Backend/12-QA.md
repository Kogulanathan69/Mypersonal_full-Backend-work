# QA, definition of done and release gates

| Gate | Required evidence |
|---|---|
| Startup | C# restore/build; Python health/test; DB readiness separate |
| Auth | invalid credentials, duplicates, token expiry, reset reuse, owner A/B isolation |
| Survey | valid/empty/corrupt/oversized, image-only uncertainty, unsafe path rejection |
| Land | rectangle/irregular, zero area/self-crossing, correct CRS, stale confirm |
| Requirements | missing/invalid/duplicate fields, reopen persisted values |
| Generation | no-land/malformed/failure/timeout, 3 distinct validated alternatives on supported fixtures, infeasible honest |
| Edit | add/move/resize/openings, collision and out-of-bound rejection, neighbor adjustment, Apply/Reject, stale version, immutable rollback |
| Confirmation | exact validated revision, explicit acknowledgment, new revision not confirmed implicitly |
| Report/share | exact version, artifact access, explicit consent, truthful request status |
| RAG | source page traceability, unknown/conflict, retrieval not legal proof |
| Admin | scoped visibility, all staff writes pending, rejection no live mutation, audit |
| Full E2E | actual integrated services and disposable DB, recorded commits/test IDs; mocked coverage distinct |

Each owner writes unit/contract tests, integration lead runs cross-module tests. Required build command names derive from actual repo. CI green is evidence only, not product acceptance. DONE = code and docs aligned, relevant tests pass, reviewer approved, QA verified, no critical unresolved security/data-integrity defect, evidence recorded. Distinguish PARTIAL/BLOCKED/REVIEW/DONE; do not assume historical test passes current commit. Seven days demo goal; production gate additionally requires security, coverage, monitoring, deployment and restore verification.
