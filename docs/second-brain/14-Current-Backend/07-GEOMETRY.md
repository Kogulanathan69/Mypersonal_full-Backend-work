# Canonical geometry, feasibility and editing

Draft canonical contract; M6 owns schema with M2/M3 and M7 review. World coordinates/longitude latitude are EPSG:4326 for map; project geometry uses explicit projected or local metric CRS, with origin and transform, axes and source units. Survey dimensions have bearing/unit provenance; never guess scale, units, angle or georeference. Compute area/perimeter from metric polygon, validate closure, self intersections, holes as supported, degeneracy and containment. Preserve raw source coordinates and corrected revision.

Geometry JSON proposed fields: schemaVersion, units=m, coordinateReference, origin, boundaryRevisionId, requirementsRevisionId, floors[{id,level,rooms,walls,openings}], stable element IDs and explicit shared wall references. Floor layout vertices metric, room polygons closed, wall thickness/segments defined; openings anchored to wall ID and offset/width; no overlapping/invalid opening axes. Coordinate transforms must round-trip with agreed tolerance. Areas derived from geometry, not arbitrary client values. Schema and tolerance signed off before implementation. JSON schema illustrative, not a substitute for topology checks.

M2 land validation: self-intersection, zero area, CRS, uncertainty. M6 authoritative floor validation: footprint, room overlap, minimum dimensions where verified, connectivity/access, opening placement, requirement match, local rules status. M3 transformations: add/move/resize/remove rooms, walls, doors, windows; candidate on copy; adjust neighbors deterministically only if valid and permitted. Validation result binds geometry hash, land and requirement revisions, rule/engine versions, severity and provenance. Separate geometry validity, functional requirement satisfaction and legal evidence. No legal-approved flag inferred from RAG relevance or Vastu. Unknown rules cannot be invented.

Generation baseline: normalize input -> buildable region based on known constraints -> allocate rooms and circulation -> candidate search -> validate -> deduplicate via normalized topology/adjacency/geometry signature -> compare computed metrics -> return exactly three on supported feasible success, otherwise diagnostics. Distinct does not mean color differences. Avoid infinite search; bound computation and report failure. RAG and AI provide proposals/context, deterministic checks remain authoritative within supported envelope. Vastu internal soft ranking only; never blocks user edits.
