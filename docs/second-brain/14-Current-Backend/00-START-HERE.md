## Precedence
Latest explicitly approved user decision > approved ADR/current contract > current V3 planning notes > historical V2. Actual source code and tests determine implementation status, not design approval. If current notes disagree with live code or each other, open a gap and ask the lead; never silently change public behavior. The six backend slot plans are proposals until roster and contract signoff. Historical files remain searchable but are not instructions.

All features require evidence. A 7-day schedule is an aggressive integration target, not a promise of production readiness. No embeddings or MCP are required to read this Markdown vault. Product RAG and the developer knowledge vault are different systems.
