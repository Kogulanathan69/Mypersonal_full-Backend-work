# End-to-end backend workflows

1. M1 authenticates, creates owner-scoped project. M2 accepts survey or approved manual measurements; extraction records known/missing/uncertain; map location is separate from exact parcel geometry. Validate normalized candidate, user confirms exact land revision.
2. M5 persists ground floor counts, additional spaces and room relationships, with later floors according to approved scope. Summary is from persisted snapshot. Save design method. Do not run full rule analysis merely at upload.
3. M6 consumes confirmed land and requirement revisions, obtains M7 source-linked applicable constraints where established, calculates feasibility; unknown rule evidence remains unknown. Job captures exact input IDs. Successful result has three distinct alternatives or return failed/infeasible with diagnostics. Re-running generation makes previous selection stale for new input; don't delete prior history.
4. M6 selects alternative; M3 initializes editor draft from exact selected geometry (manual draft if approved). Client sends edit commands and base revision; Python M3 transforms a copy; M6 validates; C# accepts/rejects atomically. AI proposal does not mutate until explicit Apply. Reject keeps current hash unchanged; stale edit -> conflict. Undo/redo must be version-aware and validated. Neighbor adjustments only when safe and visible; no silent modification.
5. M3 persists immutable revision and validation reference. Confirmation is explicit by owner and current exact validated revision. Critical errors block. Noncritical warnings may continue with acknowledgement by approved policy. New revision invalidates current confirmation; older history retained.
6. M5 generates preliminary PDF from exact confirmed revision; includes source gaps and disclaimer. Download authorized. Architect request shares only explicitly selected documents and recipient after consent; no fake accepted status. Use permitted withdraw transitions.
7. Admin/staff changes follow proposal/review/publish cycle; rules versions used in a prior plan remain traceable. See admin scope note.

Freeze real enums before code. Project state derived from valid prerequisites, not a client-controlled flag. No fabricated percentages.
