## Verified security behaviour (live)

| Control | Verification |
|---|---|
| Authentication (JWT, refresh rotation, logout-all, token_version bump) | journey 2/7, admin smoke |
| Owner-scoped access: another user's resources → 404 | journey cross-user checks (for example cross-user alternatives, versions, AI proposals and architect report access after withdrawal) |
| Admin RBAC with privileges read fresh per request, deadlock-free lock order, tamper-evident audit chain (verify endpoint) | admin smoke 65/65 |
| Architect consent: report access revoked on withdrawal (404) | journey 9 |
| Internal mTLS API → python | `mtls_tests.py` **12/12**: valid handshake. Rejected: missing client certificate, untrusted-CA client, expired client, server certificate used as a client identity, server-name mismatch, client trusting the wrong CA, and plaintext HTTP. Also checks TLS ≥1.2 with the expected identity, and that the token is still required over mTLS (missing/wrong → 401). Rotation was verified in INTERNAL-MTLS-VERIFICATION. Containers: a client without a certificate is rejected. |
| MySQL transport | `--require-secure-transport=ON`, VerifyFull + client certificate; least-privilege accounts (runtime DML only, migrator separate) |
| Request body limits | 1 MiB global (Kestrel, 413 `PAYLOAD_TOO_LARGE`); deterministic tests (P-13) |
| Rate limiting | auth-strict and expensive-operation limiters (observed 429s drove the journey cool-downs) |
| LLM safety | minimised prompt (no ids or PII); strict JSON schema plus server re-validation; one bounded command; injection refused (422); logs contain outcome codes only |
| Email | external SMTP refused unless explicitly allowed **and** STARTTLS; password from file; recipients and bodies never logged |
| Containers | non-root, read-only root, `cap_drop ALL`, `no-new-privileges`, memory/pid limits, internal network, loopback-only publish |
| Corpus identity controls | untouched; approved PDFs hash-verified read-only |
